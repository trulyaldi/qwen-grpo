# Ticket 13: end-to-end validation and final evidence

## Outputs

- **`research/l2l/final_results.json` and `research/l2l/final_report.md`** (at most three pages): generated by
  `scripts/final_report.py` from the evidence files only. It classifies each requirement as PASS, FAIL, BLOCKED or NOT
  TESTED, and derives one SHIP / DON'T SHIP verdict: SHIP only if every essential requirement is PASS. It also contains
  the silent-failure audit, stage by stage, citing only faults the tests actually injected.
- **`scripts/final_eval.py`:** the held-out test evaluation (1,066 examples) of four models, all through L2L:
  - the base model, the adapter-attached trained model, the streamed-merged model, and the LR=0 control;
  - accuracy (equal to mean reward), macro F1, invalid-response rate and prediction distribution;
  - paired-bootstrap 95% CIs;
  - policy change against base, and LoRA parameter change;
  - a data-separation check.
- **`scripts/final_run.sh`:** the final Qwen3-4B run (`configs/experiments/qwen3_4b_final.yaml`), resumable, then the
  LR=0 control (`qwen3_4b_final_lr0.yaml`), the evaluation and the report.
- **`scripts/laptop_checks.sh`:** now regenerates the report after the other checks.

## The final run's design

- **Model and system:** Qwen3-4B with L2L async, disk streaming with crash-consistent checkpoints, and the 8 GiB
  budget.
- **Data:** 1,024 balanced training prompts, within the assignment's 1–2k. 210 updates of 5 prompts × 6 completions
  use each prompt about once.
- **Held out:** the validation subset (128) only monitors training; the test split is used once, after training.
- **Negative control:** LR=0, with the trainer's own control checks.

The earlier 32-example and 512-sample sentiment runs on Qwen3-0.6B are **not** presented as satisfying the assignment.

## Known limits that the report will show

- **The GPU budget (R13) can only be BLOCKED under WSL2,** where there are no per-process nvidia-smi readings. A native
  Linux host is needed for PASS.
- **DFlash speed (R12) may FAIL** because of the batched minimum-acceptance rule (docs/l2l/12_dflash.md).
- **The memory-efficient head (R3) is not essential,** because training uses the exact full head.
